Routing defines how packets travel from one network to another. This guide compares **static** and **dynamic** routing — when to use each, configuration examples, and how they apply in both on-prem and cloud (AWS VPC) environments.

---

## Overview

| Type | Description | Use Case |
|:-----|:------------|:---------|
| **Static Routing** | Administrator manually defines routes | Small networks, lab setups, or edge routing with predictable paths |
| **Dynamic Routing** | Routers exchange routes automatically using protocols (e.g. OSPF, BGP) | Large, scalable, or frequently changing environments |

---

## Static Routing

Static routes are **manually configured** and **do not change** unless the admin modifies them. They're predictable and simple but don't adapt to network failures automatically.

### Advantages

<CardGroup cols={3}>
  <Card title="Full Control" icon="sliders">
    No route advertisement leaks
  </Card>
  
  <Card title="Low Overhead" icon="gauge-simple">
    Minimal CPU/RAM, no protocol chatter
  </Card>
  
  <Card title="Easy Auditing" icon="magnifying-glass">
    You know every path explicitly
  </Card>
</CardGroup>

### Disadvantages

<CardGroup cols={3}>
  <Card title="No Failover" icon="triangle-exclamation">
    No automatic failover
  </Card>
  
  <Card title="High Admin Overhead" icon="user-gear">
    High admin overhead at scale
  </Card>
  
  <Card title="Error Prone" icon="circle-exclamation">
    Prone to human error (typos, forgotten updates)
  </Card>
</CardGroup>

### Configuration Examples

<Tabs>
  <Tab title="Linux">
    ```bash
    # Add a static route (temporary)
    ip route add 10.20.0.0/16 via 192.168.1.1
    
    # Make persistent (RHEL/AlmaLinux)
    echo "10.20.0.0/16 via 192.168.1.1 dev eth0" >> /etc/sysconfig/network-scripts/route-eth0
    ```
  </Tab>
  
  <Tab title="Cisco IOS">
    ```bash
    Router(config)# ip route 10.20.0.0 255.255.0.0 192.168.1.1
    Router(config)# do show ip route static
    ```
  </Tab>
</Tabs>

## Dynamic Routing

Dynamic routing protocols **learn and share routes** automatically. They detect network changes and reroute traffic when links fail — ideal for large, redundant topologies.

### Common Protocols

| Protocol | Type | Notes |
|:---------|:-----|:------|
| **RIP** | Distance-vector | Obsolete; max 15 hops; good for labs |
| **OSPF** | Link-state | Hierarchical; ideal for enterprise LANs |
| **EIGRP** | Hybrid | Cisco-proprietary (now partially open) |
| **BGP** | Path-vector | Used for ISPs, multi-site, and AWS Transit Gateway |

### Advantages

<CardGroup cols={3}>
  <Card title="Auto-learns Topology" icon="brain">
    Automatically learns network topology
  </Card>
  
  <Card title="Failover Support" icon="rotate">
    Supports failover and load balancing
  </Card>
  
  <Card title="Lower Admin Work" icon="hands">
    Reduces admin workload
  </Card>
</CardGroup>

### Disadvantages

<CardGroup cols={3}>
  <Card title="Complexity" icon="gears">
    More complex to configure and troubleshoot
  </Card>
  
  <Card title="Resource Usage" icon="microchip">
    Consumes CPU/RAM for routing table updates
  </Card>
  
  <Card title="Misconfig Risk" icon="bomb">
    Protocol misconfigurations can propagate quickly
  </Card>
</CardGroup>

## Configuration Examples

<Tabs>
  <Tab title="Cisco - OSPF">
    ```bash
    Router(config)# router ospf 1
    Router(config-router)# network 10.0.0.0 0.0.0.255 area 0
    Router(config-router)# network 192.168.1.0 0.0.0.255 area 0
    Router(config)# do show ip ospf neighbor
    ```
  </Tab>
  
  <Tab title="Linux - OSPF (FRRouting)">
    ```bash
    vtysh
    router ospf
     network 10.0.0.0/24 area 0
     network 192.168.1.0/24 area 0
    ```
  </Tab>
</Tabs>

## AWS VPC Routing

| Type | Description | Example |
|:-----|:------------|:--------|
| **Static Route** | Added manually to route table | `10.0.2.0/24 → nat-0abc12345` |
| **Dynamic Route** | Propagated from VPN / Direct Connect / TGW | Automatically updates with BGP peers |

<Info>
AWS route propagation uses **BGP** under the hood when connected via VPN or Direct Connect gateways.
</Info>

---

## When to Use Which

| Scenario | Recommended |
|:---------|:------------|
| Small lab / testbed | Static |
| Branch offices with few routes | Static or OSPF stub |
| Multi-site enterprise | OSPF / EIGRP |
| Internet peering, cloud hybrid | BGP |
| AWS VPCs with VPN or TGW | Dynamic (BGP propagation) |

## Security Considerations

<CardGroup cols={2}>
  <Card title="Disable Unused Protocols" icon="power-off">

  </Card>
  
  <Card title="Authenticate Neighbors" icon="key">

  </Card>
  
  <Card title="Filter Advertisements" icon="filter">
    Filter route advertisements (prefix-lists, route-maps)
  </Card>
  
  <Card title="Prevent Route Leaks" icon="shield">
    Avoid default route leaks in hybrid environments
  </Card>
